# 3НФ

На этом этапе я проверяю, какие данные от чего зависят.

Например, телефон зависит от клиента:

**Клиент → Телефон**

Поэтому телефон находится в таблице «Клиенты», а в таблице «Заказы» достаточно хранить только ID клиента.

С товарами похожая ситуация:

**ID_товара → Наименование, Цена**

Поэтому название и цена находятся в таблице «Товары».

В результате каждая таблица содержит данные, которые относятся именно к ней, а одинаковая информация не повторяется без необходимости.

# 3НФ — Таблица «Заказы»

## Что такое 3НФ

3НФ (третья нормальная форма) — это структура базы данных, при которой неключевые поля не зависят друг от друга.

Каждая информация хранится в своей таблице, что уменьшает дублирование данных.

## Итоговые таблицы

### 1. Таблица «Клиенты»

| ID_клиента | Клиент | Телефон |

| 1 | Иванов П. | 111-11-11 |
| 2 | Петров С. | 222-22-22 |
| 3 | Сидоров А. | 333-33-33 |

**Первичный ключ:** `ID_клиента`

### 3. Таблица «Заказы»

| ID_заказа | Дата | ID_клиента |

### 4. Таблица «Состав_заказа»

**Составной первичный ключ:** `ID_заказа + ID_товара`

**Внешний ключ:** `ID_заказа` → `Заказы.ID_заказа`

**Внешний ключ:** `ID_товара` → `Товары.ID_товара`

Здесь хранится информация о том, какие товары входят в каждый заказ и в каком количестве.
